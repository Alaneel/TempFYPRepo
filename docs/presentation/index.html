Remove property_age

Why the Asymmetry?

Key Insight: The model learned the CPF-induced price discontinuity entirely from data — no CPF feature was explicitly engineered. Feature ablation validates domain knowledge, not just accuracy.
TIMING: 2 min. THIS IS THE MOST IMPORTANT SLIDE. Slow down here. "Here's the most interesting — and I'd argue the most academically significant — finding. [PAUSE] When I remove property_age from HDB Sale, MAPE jumps by 130 percentage points. [PAUSE — let the number sink in]. But for Landed, just 1.2. Why? Singapore's CPF policy. Buyers cannot use CPF to finance HDB flats with less than 60 years remaining on their lease. This creates a demand cliff — older HDB prices collapse. The model learned this price discontinuity entirely from data, without any CPF feature being engineered. Feature ablation doesn't just measure accuracy — it validates that the model has captured real economic structure. It's not a black box."

Three Agentic Enhancements

A naive LLM wrapper returns 0 results and says nothing → user lost.

🗺 Geographic Resolution

"near Orchard" → D9 + D10 + D11

Agent recognises MRT stations and landmarks, auto-expands to adjacent districts

🔄 Progressive Relaxation

0 results? Relax in order:

Price → Type → Location

12/12 recovery

Location relaxed last (hardest buyer constraint)

💬 Fallback Explanation

LLM explains what was relaxed and why

< 800ms latency

Full transparency — users stay informed

Together: passive LLM wrapper → intelligent agent with zero dead ends

TIMING: 3 min total, ~1 min per enhancement. Spend most time on Progressive Relaxation (has eval data). "Three agentic behaviours. First, geographic resolution: 'near Orchard' expands to D9, D10, D11. Second — the most important — progressive filter relaxation. If zero results, relax in priority order: price first, then type, finally location. Location last because it's the hardest constraint. 100% recovery across 12 over-constrained test cases. Third, fallback explanation: LLM explains what changed, under 800ms. Together, these turn a passive wrapper into an agent that never leaves users at a dead end."
