\chapter{Introduction}

\section{Background and Motivation}

Singapore's housing sector is characterized by a unique \textbf{dual-tier structure}, comprising a highly regulated public housing market managed by the Housing and Development Board (HDB) and a free-market private residential sector. The HDB sector houses approximately 80\% of the resident population, serving as a critical pillar of national social stability, while the private sector caters to higher-income households and investors \cite{tu2004dynamics}. Despite their regulatory separation, these two markets exhibit complex, non-linear interdependencies. The ``asset progression'' aspiration—whereby households upgrade from public to private housing—creates a dynamic flow of capital and demand that links the two tiers \cite{sing2006price}.

In the current digital era, the proliferation of online property portals such as PropertyGuru, 99.co, and SRX has led to an explosion of real estate data. This includes not only transactional records but also unstructured text descriptions, listing metadata, and visual assets. However, this data remains fragmented across disparate platforms, creating significant \textbf{information asymmetry} for stakeholders. Homebuyers, investors, and policymakers alike face challenges in obtaining a holistic view of the market, often relying on disjointed manual searches or simplistic linear analyses that fail to capture the nuances of the dual-market system.

\section{Problem Statement}

Three concrete problems motivated this project:

\begin{enumerate}
    \item \textbf{Data Fragmentation:} Critical market intelligence is siloed across competing platforms, making cross-sectional analysis difficult.
    \item \textbf{Methodological Limitations:} Traditional econometric methods (e.g., Hedonic Pricing Models) typically rely on structured variables and linear assumptions, often neglecting the rich insights embedded in unstructured data and non-linear market dynamics.
    \item \textbf{Search Usability:} Existing portals require users to navigate rigid filter interfaces, creating friction for users who wish to express nuanced, natural-language requirements.
\end{enumerate}

\section{Project Objectives}

The system built to address these problems covers the full stack from raw scraping to a user-facing web application. The specific objectives achieved are:

\begin{enumerate}
    \item \textbf{Unified Data Infrastructure:} Automated web scraping pipelines were designed and implemented to aggregate and harmonise listings from Singapore's major property portals into a single deduplicated repository.
    \item \textbf{Intelligent Property Valuation:} Per-segment gradient-boosted regression models (stratified by property type and transaction mode) were trained to estimate market values and provide SHAP-based attribution explanations.
    \item \textbf{Natural Language Interfaces:} A semantic search engine powered by Large Language Models (LLMs) was integrated, allowing users to discover properties using conversational queries.
    \item \textbf{Agentic Search and Conversational AI:} Three agentic behaviours (multi-district resolution, progressive filter relaxation, fallback explanations) and a multi-turn valuation chat assistant were implemented to extend the system beyond passive retrieval.
    \item \textbf{Actionable User Interface:} A web application exposing all AI features to end-users through a listing portal with integrated valuation panel, NL search bar, and chat assistant.
\end{enumerate}

\section{Contributions}

This report documents the individual contributions of the author within a larger team project.
The project team collectively built an end-to-end platform that aggregates data from four
portals; the author's personal contributions are as follows:

\begin{enumerate}
    \item \textbf{PropertyGuru Data Scraper.}
    The author designed and implemented the PropertyGuru web scraper, the project's largest
    data source (53,352 of 53,497 total listings, 99.7\%). The scraper supports incremental
    crawling, session resilience, and full attribute extraction including price, floor area,
    tenure, built year, and agent information.

    \item \textbf{Multi-Platform Aggregation and Deduplication Pipeline.}
    The author designed and implemented the unified aggregation layer
    (\texttt{pipeline/aggregate.py}) that consumes data from all four scrapers (built by the
    team), normalises heterogeneous schemas, and applies a composite-key deduplication
    algorithm. The pipeline ingested \textbf{86,321 raw listings} across four portals
    (PropertyGuru 55,357; SRX 24,010; 99.co 5,344; EdgeProp 1,610) and produced a clean
    deduplicated dataset of \textbf{53,497 listings}. The dedup key achieves
    \textbf{95.5\% address-field coverage}; a title-fallback strategy eliminates all
    remaining degenerate collisions (2,410 → 0).

    \item \textbf{Per-Segment AI Valuation Models with SHAP Explanations.}
    The author trained \textbf{eight independent XGBoost models} stratified by property type
    and transaction mode. Best-segment test-set MAPE: \textbf{8.90\%} (HDB Rent) and
    \textbf{8.96\%} (HDB Sale)---a \textbf{70\%} reduction relative to the mean baseline.
    Each prediction is accompanied by SHAP attribution factors exposed to the end user.

    \item \textbf{LLM-Powered Natural Language Property Search.}
    The author implemented the Claude-backed semantic search pipeline and conducted a formal
    evaluation across 47 ground-truth queries, achieving an average \textbf{F1 of 96.4\%}.

    \item \textbf{Agentic Search Enhancements.}
    Beyond basic intent extraction, the author implemented three agentic behaviours layered
    on top of the NL search pipeline: (i) \textit{multi-district geographic resolution},
    which maps proximity expressions such as ``near Orchard MRT'' to a set of adjacent
    Singapore districts (e.g., D9/D10/D11) rather than a single district, improving recall
    for location-aware queries; (ii) \textit{progressive filter relaxation}, which
    automatically retries queries with successively relaxed constraints (price $\to$ tenure
    $\to$ location) when no results are found, preventing zero-result dead ends; and (iii)
    \textit{LLM-generated fallback explanations}, where a secondary Claude call produces a
    natural-language explanation of why the original query yielded no results and what
    constraints were relaxed.

    \item \textbf{AI Valuation Chat Assistant.}
    The author implemented a multi-turn conversational assistant accessible from each
    property detail page. The assistant is provided with the listing's full attribute set
    and the XGBoost valuation estimate (including SHAP attribution factors) as context,
    enabling it to answer questions such as ``Is this fairly priced?'' or ``What factors
    drive this estimate?'' using grounded, property-specific data. An offline evaluation
    harness spanning 42 interactions across three property segments (Condominium Sale,
    HDB Rent, Landed Sale) confirmed \textbf{93\% factual consistency} and
    \textbf{100\% response relevance}.

    \item \textbf{Backend API and Frontend Web Application.}
    The author built the FastAPI backend (JWT authentication, Redis caching, RESTful listing,
    valuation, and chat endpoints) and the Next.js frontend (listing portal, detail page with
    AI valuation panel, NL search bar, and chat assistant panel).
\end{enumerate}
